Your mission is to DESIGN AND BUILD from scratch a world-class macOS + Windows desktop application for creators.

Do not patch or reproduce the architecture of the previous video editor.

Treat this as a GREENFIELD PRODUCT.

The goal is NOT to build another traditional video editor.

The goal is to build:

# THE FASTEST CREATOR PRE-EDITOR

A focused desktop application that transforms raw talking-head footage into a clean, polished, captioned first cut.

Core idea:

RAW FOOTAGE  
→ CLEAN SPEECH  
→ REMOVE BAD PARTS  
→ SMART CAPTIONS  
→ REVIEW  
→ EXPORT / SEND TO EDITOR

The product should combine the best workflow ideas from Recut-style rough-cutting with a significantly more powerful transcript and subtitle workflow.

Do NOT blindly clone Recut.

At minimum, match the important rough-cut capabilities users expect from tools like Recut, then exceed them in measurable areas:

- smarter speech cleanup
- filler detection
- retake detection
- false-start detection
- repetition detection
- transcript editing
- word-accurate captions
- animated caption presets
- better review UX
- faster perceived performance
- safer automatic edits
- professional export workflow

Do not claim “100% better” through marketing language.

Make the product objectively better on defined workflows and measurable metrics.

# FORCED ALIGNMENT / WORD TIMING

High-quality captions require accurate word timing.

Design the speech layer so transcription and alignment are separate concepts.

TRANSCRIPTION:

What was spoken?

ALIGNMENT:

Exactly when was each word spoken?

Store:

word

startTime

endTime

confidence

Example:

{
  text: "build",
  start: 12.421,
  end: 12.804,
  confidence: 0.97
}

For languages where additional alignment provides meaningful accuracy improvements, support an alignment stage.

If full forced alignment is unavailable for a language:

fall back gracefully to high-quality word timing + VAD boundary refinement.

Never block the entire workflow because one optional alignment backend is unavailable.

# VAD

Use a reliable voice activity detection layer.

Purpose:

- detect real speech boundaries
- avoid noise being mistaken for speech
- improve silence detection
- accelerate transcription
- improve cut boundaries

Silence detection must NOT be only:

volume < threshold

Combine:

VAD  
+ audio energy  
+ speech timestamps  
+ surrounding context

---

# SMART SILENCE

Do not simply delete all silence.

Implement PAUSE COMPRESSION.

Modes:

Natural

Balanced

Fast

Custom

Example:

3.4 second silence

Natural:

retain ~600–900ms depending on context

Balanced:

retain ~350–500ms

Fast:

retain ~150–300ms

Exact values should be tuned through testing.

Different pauses serve different purposes.

Detect:

- sentence boundary
- breathing pause
- thinking pause
- intentional dramatic pause

Avoid robotic edits.

# RETAKE DETECTION

This is a KEY DIFFERENTIATOR.

Detect when someone repeats the same idea because the first take was bad.

Signals may include:

- lexical similarity
- semantic similarity
- sentence restart patterns
- correction language
- short temporal distance
- incomplete first phrase
- stronger completion in second attempt

Example:

Take A:

“This tool helps you edit...”

Take B:

“This tool helps you edit your footage much faster.”

Suggest:

Remove A

Keep B

But provide confidence.

Do not delete automatically if confidence is low.

---

# REPETITION DETECTION

Detect repeated phrases or repeated meaning.

Example:

“We built this specifically for designers.”

“This application was designed specifically for designers.”

Mark:

POSSIBLE RETAKE

Allow:

Keep A

Keep B

Remove A

Remove B

Do not automatically remove semantic repetitions at low confidence.
